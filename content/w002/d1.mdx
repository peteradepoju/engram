<Step n={1} title="Why arrays" minutes={15} />

Your Week 1 code used Python lists and loops. That works for a few numbers. But the dataset you will analyse in Part 2 (Steinmetz et al., 2019, this week's deep read) has about 30,000 neurons. A Python list stores each number as a separate object scattered around memory, and a loop handles them one at a time.

A **NumPy array** stores numbers of one type in a single block of memory, and its operations run in compiled C code over the whole block at once. That makes code shorter (no loops) and much faster. Almost every scientific Python library, from SciPy to PyTorch, is built on this idea.

<PyCell code={String.raw`
  import numpy as np

  rates = np.array([12.0, 15.5, 9.8, 22.1])     # from a list
  print(rates, rates.dtype, rates.shape)

  zeros = np.zeros((3, 4))                       # 3 rows, 4 columns of zeros
  t = np.arange(0, 1, 0.25)                      # 0, 0.25, 0.5, 0.75
  grid = np.linspace(0, 1, 5)                    # 5 evenly spaced points including both ends
  print(zeros.shape, t, grid)

  # Arithmetic works element by element, with no loop.
  print(rates * 2)
  print(rates - rates.mean())
`} />

Three properties describe every array:

- `shape`: the size along each axis, as a tuple. `(4,)` is one axis of length 4; `(3, 4)` is 3 rows and 4 columns.
- `ndim`: the number of axes, the length of the shape.
- `dtype`: the type of every element, such as `float64` or `int64`. One array, one type.

<Callout kind="warning">
`np.arange(0, 1, 0.1)` can give 10 or 11 numbers because of rounding in floating-point arithmetic. When you want a fixed number of points, use `np.linspace`.
</Callout>

<Step n={3} title="Shapes and axes" minutes={30} />

Most neural data is naturally a 3D array: **neurons by trials by time bins**. Each number is a spike count (or a firing rate) for one neuron, on one trial, in one small window of time. Click through the figure to see what each average leaves.

The key word is `axis`. `data.mean(axis=1)` averages along axis 1 (trials) and returns an array without that axis. This one argument replaces a nested loop.

<PyCell code={String.raw`
  import numpy as np
  rng = np.random.default_rng(0)
  n_neurons, n_trials, n_bins = 5, 4, 8
  data = rng.poisson(3, size=(n_neurons, n_trials, n_bins))   # spike counts

  print("shape:", data.shape, " ndim:", data.ndim, " size:", data.size)
  print("trial-averaged response of each neuron:", data.mean(axis=1).shape)
  print("population activity per trial and bin:", data.mean(axis=0).shape)
  print("total spikes per neuron:", data.sum(axis=(1, 2)))
`} />

A useful habit: **write the shape next to every array** in a comment, with the meaning of each axis. Most bugs in analysis code are shape bugs, and this habit catches them.

<Derivation title="How an array finds an element: strides">
  <div>

The array is one long block of memory. To find element `data[i, j, k]` NumPy needs its position in that block.

  </div>
  <div>

For shape $(N, K, T)$ stored row by row (C order), moving one step along the last axis moves 1 element; along the middle axis $T$ elements; along the first axis $K T$ elements.

  </div>
  <div>

So the position is $i \cdot KT + j \cdot T + k$. These step sizes, times the bytes per element, are the array's `strides`.

  </div>
  <div>

Slicing and transposing only change the shape and strides, not the data. That is why they are instant and why a slice is a **view** of the original, not a copy (more tomorrow).

  </div>
</Derivation>

<PyCell code={String.raw`
  x = np.zeros((5, 4, 8))
  print("strides in bytes:", x.strides, " (each float64 is 8 bytes)")
  print("transposed shape:", x.T.shape, " strides:", x.T.strides)
`} />

<Step n={4} title="Speed: loops against vectors" minutes={20} />

<PyCell code={String.raw`
  import time
  x = np.random.default_rng(1).normal(size=1_000_000)

  t0 = time.perf_counter()
  total = 0.0
  for v in x:
      total += v * v
  loop_time = time.perf_counter() - t0

  t0 = time.perf_counter()
  total_np = np.sum(x * x)
  vec_time = time.perf_counter() - t0

  print(f"loop: {loop_time*1000:.1f} ms   vectorised: {vec_time*1000:.2f} ms   speed-up: {loop_time/vec_time:.0f}x")
`} />

The speed-up is usually between 20 and 200 times, depending on the machine. In the browser everything is slower, but the ratio is similar. The lesson: **if you write a loop over the elements of an array, look for an array operation instead.**

<Key title="Before you go">
<ul>
<li>Arrays store one type of number in one block of memory; operations run over the whole block.</li>
<li>Think in shapes: neural data is usually (neurons, trials, time).</li>
<li>Reductions with `axis` replace nested loops.</li>
<li>Slices and transposes are views: new shape and strides, same data.</li>
</ul>
</Key>
