<Step n={1} title="Why figures matter" minutes={10} />

A paper is read in a strange order. Most readers look at the title, the abstract and then the figures. If the figures are clear, they read on. If not, they move to the next paper. A good figure makes one point that a reader can see in a few seconds; the caption and the text add the detail.

Matplotlib is the plotting library underneath most scientific Python. It can do almost anything, which is both its strength and its difficulty: the defaults are fine for exploring data, but almost never right for a paper. This week you learn to take control of every part.

<Step n={2} title="The anatomy of a figure" minutes={25} />

Every Matplotlib figure is a tree of objects. The **Figure** is the whole canvas. It holds one or more **Axes**: each Axes is a plotting area with its own coordinate system, ticks, labels and data. Click the parts below.

Matplotlib has two ways of working:

- The **pyplot** style, `plt.plot(...)`, `plt.xlabel(...)`, acts on whichever axes is current. It is quick for a one-off look.
- The **object-oriented** style, `fig, ax = plt.subplots()` then `ax.plot(...)`, `ax.set_xlabel(...)`, names each object. It is clearer, works the same with one panel or twenty, and is what this course uses.

<PyCell code={String.raw`
  import numpy as np
  import matplotlib.pyplot as plt

  oris = np.arange(0, 180, 22.5)
  rate = 4 + 26 * np.exp(2.2 * (np.cos(2 * np.radians(oris - 90)) - 1))

  fig, ax = plt.subplots(figsize=(5, 3))
  ax.plot(oris, rate, marker="o")
  ax.set_xlabel("orientation (deg)")
  ax.set_ylabel("firing rate (Hz)")
  ax.set_title("A V1 neuron's tuning curve")
  plt.show()
`} />

Writing plotting code as a function that takes an `ax` is a habit worth keeping. The same function can then draw into a single figure, one panel of a big figure, or a slide, and you can test it, as the checks above just did.

<Step n={4} title="Several panels" minutes={25} />

Most figures in a paper have several panels labelled A, B, C. `plt.subplots(rows, cols)` returns the figure and an array of axes. Options worth knowing: `sharex=True` or `sharey=True` to share axes, and `layout="constrained"` to stop labels overlapping.

<PyCell code={String.raw`

<Prove title="How much do the error bars shrink?" task="The SEM is $s/\sqrt{n}$. If you go from 10 trials to 20, by what factor do the error bars shrink (on average)? How many trials would you need to halve the error bars of the 10-trial panel?">

From 10 to 20 trials the SEM changes by $\sqrt{10}/\sqrt{20} = 1/\sqrt{2} \approx 0.71$, so the bars shrink by about 29 per cent.

To halve them you need $\sqrt{10/n} = 1/2$, so $n = 40$ trials. Halving uncertainty always costs four times the data.

</Prove>

<Step n={5} title="Saving and style" minutes={10} />

For a paper, save figures as **vector** files (PDF or SVG), which stay sharp at any size, and make the figure the size it will be printed so fonts come out right. A single column in most journals is about 8.5 cm (3.3 inches) wide.

<PyCell code={String.raw`
  plt.rcParams.update({"font.size": 9, "axes.spines.top": False, "axes.spines.right": False})
  fig, ax = plt.subplots(figsize=(3.3, 2.4), layout="constrained")
  plot_tuning(ax, oris, counts, 0.5)
  fig.savefig("tuning.pdf")              # vector: for papers
  fig.savefig("tuning.png", dpi=300)     # bitmap: for slides and the web
  import os; print([f for f in os.listdir(".") if f.startswith("tuning")])
  plt.show()
  plt.rcdefaults()
`} />

<Key title="Before you go">
<ul>
<li>A Figure holds Axes; draw on Axes with the object-oriented interface.</li>
<li>Every axis gets a quantity and a unit; every error bar gets a definition in the caption.</li>
<li>Plotting functions that take an `ax` are reusable and testable.</li>
<li>Save at print size as PDF or SVG.</li>
</ul>
</Key>
