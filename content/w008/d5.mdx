<Step n={1} title="Computational graphs" minutes={20} />

Any calculation can be drawn as a **computational graph**: nodes are quantities, and arrows show which quantities are computed from which. The **forward pass** evaluates the graph from inputs to the loss. The **backward pass** then visits the nodes in reverse order and computes, for each one, the derivative of the loss with respect to it, written $\bar{v} = \partial L/\partial v$ (read "v bar", sometimes called the adjoint).

The rule at every node is the chain rule. If $v$ feeds into nodes $u_1, \dots, u_k$, then

$$
\bar{v} = \sum_{j} \bar{u}_j\,\frac{\partial u_j}{\partial v}
$$

The sum appears because a change in $v$ affects the loss along every path out of it (the multivariable chain rule: contributions along separate paths add).

<Step n={2} title="Backpropagation in a two-layer network" minutes={35} />

A network with one hidden layer of tanh units and a linear output, applied to a batch of $T$ inputs stacked as rows of $X$:

$$
Z = XW_1 + \mathbf{b}_1, \quad H = \tanh(Z), \quad \hat{\mathbf{y}} = H\mathbf{w}_2 + b_2, \quad L = \frac{1}{2T}\lVert\hat{\mathbf{y}} - \mathbf{y}\rVert^2
$$

<Derivation title="The backward pass">
  <div>

Start at the output. $\bar{\hat{\mathbf{y}}} = \partial L/\partial\hat{\mathbf{y}} = (\hat{\mathbf{y}} - \mathbf{y})/T$, one error per example.

  </div>
  <div>

The output layer is linear, so (as for the linear neuron on Day 4) $\bar{\mathbf{w}}_2 = H^\top\bar{\hat{\mathbf{y}}}$ and $\bar{b}_2 = \sum_t\bar{\hat{y}}_t$. The error is sent back to the hidden units through the same weights: $\bar{H} = \bar{\hat{\mathbf{y}}}\,\mathbf{w}_2^\top$.

  </div>
  <div>

Through the nonlinearity, element by element: $\bar{Z} = \bar{H} \odot (1 - H^2)$, where $\odot$ multiplies entries pairwise and $1 - \tanh^2$ is tanh's slope (Day 2).

  </div>
  <div>

Finally the first layer, again linear: $\bar{W}_1 = X^\top\bar{Z}$ and $\bar{\mathbf{b}}_1 = \sum_t \bar{Z}_t$ (summing over the rows). Each weight's gradient is its input times the error signal arriving at its output, the same pattern as Day 3, now for whole matrices.

  </div>
</Derivation>

  import numpy as np
  def num_grad(p, name, h=1e-6):
      g = np.zeros_like(np.asarray(p[name], dtype=float))
      it = np.nditer(g, flags=["multi_index"])
      for _ in it:

          q[name][i] -= 2 * h; Lm = loss(q, X, y)
          g[i] = (Lp - Lm) / (2 * h)
      return g

      Z, H, yhat = forward(p, X)
      T = len(y)
      d_yhat = (yhat - y) / T
      g = {}
      g["w2"] = H.T @ d_yhat
      g["b2"] = np.sum(d_yhat)
      dH = np.outer(d_yhat, p["w2"])
      dZ = dH * (1 - H ** 2)
      g["W1"] = X.T @ dZ
      g["b1"] = dZ.sum(axis=0)
      return g

The backward pass costs about the same as the forward pass: the same matrix multiplications, run with transposed matrices. The numerical check needed two full forward passes for each of the 65 parameters. With a million parameters backpropagation needs roughly two or three passes' worth of work, against two million for finite differences. That answers the prediction, and it is why training large networks is possible at all.

<Step n={3} title="Automatic differentiation" minutes={30} />

Writing backward passes by hand is error-prone. Libraries such as PyTorch and JAX do it automatically: every operation records how to pass gradients back to its inputs, and calling `backward()` walks the graph in reverse. This is **reverse-mode automatic differentiation**, and backpropagation is its special case for neural networks. Here is the core of such an engine in a few lines, adapted from Andrej Karpathy's teaching library *micrograd* (MIT licence).

solution={String.raw`
  import math

  class Value:
      """A number that remembers how it was computed, so gradients can flow back through it."""
      def __init__(self, data, parents=()):
          self.data, self.grad, self._parents, self._backward = data, 0.0, parents, lambda: None

      def __add__(self, other):
          other = other if isinstance(other, Value) else Value(other)
          out = Value(self.data + other.data, (self, other))
          def _backward():
              self.grad += out.grad            # d(a + b)/da = 1
              other.grad += out.grad
          out._backward = _backward
          return out

      def __mul__(self, other):
          other = other if isinstance(other, Value) else Value(other)
          out = Value(self.data * other.data, (self, other))
          def _backward():
              self.grad += other.data * out.grad
              other.grad += self.data * out.grad
          out._backward = _backward
          return out

      def tanh(self):
          t = math.tanh(self.data)
          out = Value(t, (self,))
          def _backward():
              self.grad += (1 - t ** 2) * out.grad
          out._backward = _backward
          return out

      def backward(self):
          order, seen = [], set()
          def visit(v):                        # topological order: every node after its inputs
              if v not in seen:
                  seen.add(v)
                  for p in v._parents:
                      visit(p)
                  order.append(v)
          visit(self)
          self.grad = 1.0
          for v in reversed(order):
              v._backward()

  w, x, b = Value(0.8), Value(1.5), Value(-0.2)
  r = (w * x + b).tanh()
  r.backward()
  print("r =", round(r.data, 4), " dr/dw =", round(w.grad, 4), " dr/dx =", round(x.grad, 4), " dr/db =", round(b.grad, 4))

The `+=` matters: in `a * b + a` the value `a` is used twice, and the gradients from both uses must add, exactly the sum over paths in Step 1. With a few more operations (powers, exponentials, subtraction) this engine can train small networks; PyTorch is the same idea, operating on arrays and running on GPUs.

<Prove title="Why backpropagation is cheap" task="For a chain of L stages with one scalar input and output, the forward pass costs about L operations. Compare the cost of the gradient with respect to all L stage parameters computed (a) by finite differences and (b) by the backward pass.">

(a) Finite differences need two forward passes per parameter, so about $2L \times L = 2L^2$ operations.

(b) The backward pass starts with $\bar{h}_L = 1$ and computes $\bar{h}_{l-1} = \bar{h}_l\,f_l'(h_{l-1})$, one multiplication per stage, reusing the forward values. Each parameter's gradient is then $\bar{h}_l$ times one local derivative. That is about $2L$ operations, a constant multiple of the forward pass.

The saving is the reuse: $\bar{h}_l$ is the product of all the derivatives after stage $l$, shared by every earlier stage. In general, reverse mode computes the gradient of one output with respect to any number of inputs at a small constant multiple of the cost of evaluating the function.

</Prove>
