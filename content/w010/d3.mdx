<Step n={1} title="What convolution does" minutes={20} />

The **convolution** of two sequences $f$ and $g$ is

$$
(f * g)[n] = \sum_m f[m]\,g[n - m]
$$

and for functions of continuous time, $(f * g)(t) = \int f(s)\,g(t - s)\,ds$. Two equivalent pictures:

- **Spread every input.** Each sample $f[m]$ places a copy of $g$, scaled by $f[m]$ and shifted to start at $m$; the output is the sum of all copies. For a spike train, every spike drops a copy of the kernel.
- **Slide and weight.** Each output $(f * g)[n]$ is a weighted sum of the inputs near $n$, with weights given by $g$ flipped and shifted. This is the moving average picture.

Convolution is linear and shift-invariant: delay the input and the output is delayed by the same amount, and the response to a sum of inputs is the sum of the responses. Every linear, shift-invariant system is a convolution with its response to a single impulse, its **impulse response**. Yesterday's membrane is one, with impulse response $\frac{1}{\tau}e^{-t/\tau}$.

`np.convolve` has three modes. `'full'` (the default) returns every position where the sequences overlap at all, length $N + M - 1$. `'same'` returns the central part with the length of the first input, which for a symmetric kernel keeps the output aligned with the input. `'valid'` returns only positions of complete overlap. For a causal kernel, one that is zero for negative times, take the first $N$ samples of `'full'` instead, as you did yesterday.

<Prove title="Smoothing preserves the spike count" task="Show that if the kernel g has area 1 ($\sum_n g[n]\,\Delta t = 1$), then the convolution of a spike train (spikes of height $1/\Delta t$) with g has the same total area as the spike train: the number of spikes. Why must smoothing kernels be normalised?">

Sum the convolution over all $n$ and swap the order of summation:

$\sum_n (f * g)[n] = \sum_n\sum_m f[m]\,g[n - m] = \sum_m f[m]\sum_n g[n - m] = \left(\sum_m f[m]\right)\left(\sum_k g[k]\right)$, with $k = n - m$.

The area of a sequence sampled every $\Delta t$ is its sum times $\Delta t$. A spike train with height $1/\Delta t$ per spike has area equal to the number of spikes. Convolving with an extra factor of $\Delta t$ (to approximate the integral), the result has area $(\text{spike count}) \times (\text{area of } g) = $ spike count when the kernel's area is 1.

An unnormalised kernel would multiply every estimated rate by its area, so a wider box (with height 1) would report proportionally higher rates. Normalising makes the estimate an average rate in spikes per second whatever the width.

A 2 ms kernel follows every chance spike (its error is mostly **variance**); an 80 ms kernel flattens the 40 ms peak (mostly **bias**). The 20 ms kernel is best here. That answers the prediction, but the best width depends on how many trials you have and how fast the rate changes, which in real data you do not know.

<Step n={4} title="Choosing the width honestly" minutes={30} />

You cannot compare with the true rate in a real experiment. But you can split the trials: smooth the average of half of them, and see how well it predicts the raw PSTH of the other half. Because the two halves have independent noise, the expected squared difference is the error against the true rate plus a constant (the noise variance of the held-out half), so the width that minimises it estimates the best width. Shimazaki and Shinomoto (2010), today's paper, derived a way to do this from a single set of trials; splitting is the simplest version of the same idea, and the cross-validation of Week 5 applied to smoothing.

Cross-validation picks 40 ms, a little wider than the true best of 20 ms. That is expected: the estimate was built from only half the trials, and noisier data deserve more smoothing. With the full set you would use a slightly narrower kernel than cross-validation suggests. The method needed nothing but the data, which is the point.

<Key title="Before you go">
<ul>
<li>Convolution spreads a copy of the kernel at every input sample and adds them up.</li>
<li>Linear, shift-invariant systems are convolutions with their impulse response.</li>
<li>Smoothing spike trains with a normalised kernel estimates the firing rate; the width trades bias against variance.</li>
<li>Choose the width by cross-validation over trials, not by eye.</li>
</ul>
</Key>
