<Step n={1} title="Why a standard" minutes={20} />

Every laboratory used to store data its own way: MATLAB structures, custom binary files, folders of text. Reusing someone else's recording meant weeks of reverse engineering. **Neurodata Without Borders** (NWB) is a common format for neurophysiology, designed by a consortium of laboratories and the Allen Institute, and described by Rübel and colleagues (2022). An NWB file holds the raw and processed data together with the metadata needed to interpret them: the subject, the devices, the electrodes and their brain locations, the stimuli and the behaviour. The **DANDI Archive** hosts thousands of NWB datasets, with the code to read each.

Under the hood, an NWB file is an **HDF5** file: a hierarchical container in which **groups** behave like folders, **datasets** are typed arrays, and **attributes** are small pieces of metadata attached to either. HDF5 can read a slice of a large dataset without loading the rest, which matters when a single file holds hours of recordings from hundreds of channels.

The file holds twelve datasets in a tree: subject metadata under `general`, five columns of the trials table under `intervals/trials`, the electrodes table, and four datasets for the units. Notice that the 24 units' spike times are a single dataset of about 140,000 numbers, not 24 arrays, which answers the prediction. Real NWB files follow the same plan with many more parts: raw voltage traces in `acquisition`, derived signals such as LFP or calcium traces in `processing`, and stimulus presentations in `stimulus`.

<Step n={3} title="Ragged arrays: units and spikes" minutes={30} />

Units fire different numbers of spikes, so their spike times do not fit in a rectangular array. NWB stores them as a **ragged array**: one long dataset, `spike_times`, holding every unit's spikes end to end, and an index, `spike_times_index`, giving the position where each unit's spikes end. Unit $k$'s spikes run from `index[k-1]` (or 0 for the first unit) up to `index[k]`. One array plus one index is far faster to write and read than thousands of small arrays, and HDF5 can read any one unit's slice without touching the others.

Unit 0, in VISp, fired about 4,700 spikes; units 8 and 16 a little over 3,000 and 2,800. Each was read with one slice of one dataset. The same pattern appears throughout NWB wherever rows have different lengths: spike waveforms, electrodes per unit, and the timestamps of events within trials. <Step n={4} title="Trials and alignment" minutes={25} />

The trials table is a set of columns of equal length, one row per trial: start and stop times, the stimulus, the animal's choice and anything else the experimenter recorded. Almost every analysis starts by aligning spikes to an event in this table, here stimulus onset, and counting them in small bins.

<Callout kind="note">

With a real dataset, the same steps use `pynwb` and `dandi`, which you can run in the Colab notebook for today (they need network access, which the in-page Python does not have). For example, to stream one session of the IBL Brain Wide Map without downloading it all:

```python
from dandi.dandiapi import DandiAPIClient
from pynwb import NWBHDF5IO
import remfile, h5py

with DandiAPIClient() as client:
    asset = client.get_dandiset("000409").get_assets_by_glob("*.nwb").__next__()
    url = asset.get_content_url(follow_redirects=1, strip_query=True)
io = NWBHDF5IO(file=h5py.File(remfile.File(url), "r"), load_namespaces=True)
nwb = io.read()
print(nwb.trials.to_dataframe().head())
print(nwb.units.to_dataframe()[["spike_times"]].head())
```

The DANDI identifier and file layout differ from dataset to dataset, so check each dataset's page on dandiarchive.org for its own example code.
