<Step n={1} title="Lifting into features" minutes={25} />

A **feature map** $\phi$ sends each input $\mathbf x$ to a vector of features, and a linear model in $\phi(\mathbf x)$ is a nonlinear model in $\mathbf x$. Add the products and squares of the inputs, and a linear classifier can draw conic boundaries; add higher powers, and almost any shape.

A neuroscience example of the same idea: in a task where the right answer depends on the combination of a stimulus and a context (an exclusive or), neurons that respond only to the stimulus or only to the context cannot be read out linearly, while neurons with **nonlinear mixed selectivity**, responding to particular combinations, make the answer linearly decodable. Such neurons act like a feature map, and they are common in prefrontal cortex.

On the raw inputs, logistic regression is right on 59.8% of test trials, barely above chance: no straight line splits the four quadrants of an exclusive or. Adding the single feature $x_1x_2$, whose sign *is* the answer, takes it to 98.3%. The model is still linear, in three features instead of two; the work was done by choosing the right feature. In general we do not know which features to add, which is where kernels come in: they let the model use a vast set of candidate features at once.

<Step n={2} title="Inner products without features" minutes={30} />

All the products of up to $q$ inputs make a feature space that grows like $d^q$. But many learning algorithms touch the data only through inner products $\phi(\mathbf x)^\top\phi(\mathbf x')$, and for some feature maps that inner product has a shortcut. For the **polynomial kernel**,

$$
k(\mathbf x, \mathbf x') = (1 + \mathbf x^\top\mathbf x')^q = \phi(\mathbf x)^\top\phi(\mathbf x'),
$$

where $\phi$ contains every monomial up to degree $q$, each scaled by a suitable constant. Computing the left side costs one inner product in the original space. Replacing inner products by kernel evaluations, and never forming $\phi$, is the **kernel trick**.

The explicit six-feature map and the kernel give the same number, 0.140907, to six places. The counting shows why this matters. Degree-2 features of 100 inputs number 5,151; degree-3 features 176,851, which answers the prediction; with 1,000 inputs, 168 million. The kernel always costs one inner product of the original inputs. Any algorithm that can be written in terms of inner products, ridge regression tomorrow and the support vector machine later this week, can therefore use these huge feature spaces for the price of an $n \times n$ matrix of kernel values.

<Step n={3} title="Infinitely many features" minutes={20} />

The most used kernel is the **Gaussian** (or RBF) kernel, $k(\mathbf x, \mathbf x') = \exp(-\gamma\lVert\mathbf x - \mathbf x'\rVert^2)$. Expanding $e^{2\gamma\mathbf x^\top\mathbf x'}$ as a power series shows that its feature map contains monomials of every degree, infinitely many features, yet each kernel value costs one distance. It measures similarity: 1 for identical inputs, falling towards 0 as they move apart on the scale $1/\sqrt{\gamma}$. A linear model in its feature space is a weighted sum of bumps centred on the training examples, which is why kernel methods with this kernel can fit almost any smooth function.

<Step n={4} title="What makes a kernel" minutes={30} />

Not every similarity function is an inner product in some feature space. **Mercer's condition** says $k$ is a valid kernel exactly when every Gram matrix $K_{ij} = k(\mathbf x_i, \mathbf x_j)$ it produces is symmetric and positive semi-definite, that is, has no negative eigenvalues. Sums and products of kernels are kernels, which is how new ones are built.

The Gaussian kernel, the polynomial kernel and their sum all have smallest eigenvalues at or above zero (the polynomial kernel's is zero to rounding error, because its six-dimensional feature space cannot span 40 points). The negative distance, which looks like a perfectly reasonable similarity, has an eigenvalue of −97: there is no feature space in which it is an inner product, and an algorithm that assumed otherwise could try to minimise a function that has no minimum. The eigenvalue check is a practical test for any home-made similarity measure, for example between spike trains or behavioural sequences, before it is used as a kernel.
