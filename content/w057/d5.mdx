<Step n={1} title="A kernel is a similarity" minutes={20} />

A Gaussian kernel says that trials are similar when their population vectors are close, on the scale set by its width. Too narrow, and every trial is similar only to itself, so the method can memorise but not generalise; too wide, and all trials look alike. In between, the kernel matrix shows the structure of the data.

Beyond the width, the *kind* of kernel is a modelling choice. A linear kernel says that only linear combinations of features matter; a polynomial kernel adds interactions up to some order; a Gaussian kernel allows any smooth function. Kernels can be built for structured objects too, such as spike trains, sequences or graphs, by deciding what makes two of them alike.

<Step n={2} title="Mixed selectivity and nonlinear readout" minutes={35} />

In a context-dependent task, the correct response is the exclusive or of the stimulus (A or B) and the context (1 or 2). Population P has **pure selectivity**: each neuron's rate depends linearly on the stimulus, the context, or both added together. Population M also contains neurons with **nonlinear mixed selectivity**, responding to particular combinations. Rigotti and colleagues argued that prefrontal cortex looks like M (Week 46). Decode the response from each with a linear and a Gaussian-kernel SVM.

From the pure-selectivity population, the linear decoder is exactly at chance (49.9%): every neuron's response is a sum of a stimulus effect and a context effect, so any linear combination of them is too, and the exclusive or cannot be written that way. The Gaussian-kernel decoder reads the same neurons perfectly (100%), by carving the four stimulus-context clusters apart nonlinearly. Add fifteen neurons with nonlinear mixed selectivity and the linear decoder is perfect too. The two populations carry the same information, but only one makes it linearly available; that is the sense in which mixed selectivity simplifies the job of downstream neurons, which Rigotti and colleagues argued is why prefrontal cortex has so much of it.

<Step n={3} title="Kernel PCA" minutes={25} />

Principal component analysis needs only the matrix of inner products between centred examples, so it too can be kernelised. Schölkopf, Smola and Müller, today's paper, showed that the principal components in a kernel's feature space come from the eigenvectors of the **centred** kernel matrix $\tilde K = HKH$, with $H = I - \frac1n\mathbf 1\mathbf 1^\top$: the projection of example $i$ onto component $k$ is $\sqrt{\lambda_k}\,v_{ik}$. With a Gaussian kernel, kernel PCA can unfold structure that ordinary PCA, which only finds linear directions, cannot.

Ordinary PCA finds only linear directions, and no straight projection separates two concentric rings (68% at best). Kernel PCA's first two components are not radial either: with the Gaussian kernel they describe position *around* the rings, the largest structure in the kernel matrix. The third component is radial and separates the rings perfectly (100%). So kernel PCA can expose nonlinear structure, but the order of its components depends on the kernel width as well as the data, and which component matters has to be checked rather than assumed, the same lesson as for linear PCA in Week 25.

<Step n={4} title="A kernel for spike trains" minutes={25} />

How similar are two spike trains? Smooth each with a Gaussian of width $\tau$ and take the inner product of the smoothed traces. Because it is an inner product of features (the smoothed traces), it is a valid kernel, closely related to the van Rossum distance of Week 34. Two stimuli here evoke the same number of spikes, but stimulus A tends to fire early in the trial and B late.

Both stimuli evoke about eight spikes, so the spike-count decoder is at chance (49.4%). The spike-train kernel decoder, which compares the smoothed time courses, is right on 99.9% of trials, which answers the prediction. The kernel width, 50 ms here, sets which timing differences count: much narrower and only near-coincident spikes would look alike; much wider and the kernel would approach a count. Comparing decoders across widths is a principled way to ask at what timescale a neuron's spikes carry information, the question raised by Mainen and Sejnowski's reliability experiments in Week 31.
