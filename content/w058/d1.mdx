<Step n={1} title="Questions as a model" minutes={20} />

A **decision tree** partitions the input space into rectangular regions by a sequence of binary splits on single features, and predicts the majority class (or the mean target) in each region. Its appeal is that each prediction comes with a short explanation: the path of questions that led to it. Quinlan's 1986 paper, today's paper, introduced the ID3 algorithm, one of the two classic ways of growing trees (the other, CART, came from Breiman, Friedman, Olshen and Stone). Both grow trees greedily: at each node, choose the single split that most reduces impurity, then repeat in each child.

<Step n={2} title="Impurity" minutes={25} />

A node is **pure** if all its examples share a label. With class proportions $p_k$, two common measures of impurity are the **Gini impurity**, $G = 1 - \sum_k p_k^2$, the chance that two randomly drawn examples have different labels, and the **entropy**, $H = -\sum_k p_k\log_2 p_k$, from Week 20. Both are zero for a pure node and largest for evenly mixed ones. A split's quality is the drop from the parent's impurity to the size-weighted average of its children's.

  import numpy as np
  import matplotlib.pyplot as plt
  r = np.random.default_rng(581)

  def gini(y):
      p = np.bincount(y) / len(y)
      return 1 - np.sum(p ** 2)

  def entropy(y):
      p = np.bincount(y) / len(y); p = p[p > 0]
      return -np.sum(p * np.log2(p))

  def split_gain(y, left, impurity):
      nl, nr = left.sum(), (~left).sum()
      return impurity(y) - (nl * impurity(y[left]) + nr * impurity(y[~left])) / len(y)

The parent node, half and half, has Gini impurity 0.5. Each child is 90% one class, with impurity $1 - 0.9^2 - 0.1^2 = 0.18$, so the split reduces the weighted impurity from 0.5 to 0.18, a gain of 0.32, which answers the prediction. In entropy, the same split gains 0.53 of the parent's 1 bit. The two measures nearly always rank splits the same way; Gini is slightly cheaper to compute, which is why CART and most software default to it.

<Step n={3} title="Growing a tree" minutes={40} />

Three cell types are recorded: fast-spiking interneurons (narrow spikes, high rates), somatostatin-like interneurons (medium spikes, moderate rates, some bursting) and pyramidal cells (wide spikes, low rates, frequent bursts). Each neuron is described by spike width, mean firing rate, burst index and two uninformative features. The best split for a node is found by sorting each feature and scanning every threshold between distinct values, using cumulative class counts so the scan is vectorised.

The tree's first question is spike width, at 0.55 ms, which sets the pyramidal cells apart from the two interneuron types; its next questions use spike width again and then firing rate. It never consults the two noise features or the burst index, because at every node some other split was purer. On new neurons it is right 92% of the time, and its rules can be read aloud, which is what makes trees attractive for typing cells. Notice also the leaves holding only a handful of neurons, such as the one with [0, 0, 2]: those are the tree starting to fit noise, the subject of tomorrow.

<Step n={4} title="Trees for regression" minutes={20} />

For a continuous target the leaf predicts the mean, and impurity is the variance (squared error) within a node. A tree of depth $d$ is then a piecewise-constant function with up to $2^d$ steps. Fit regression trees of increasing depth to a neuron's firing rate as a function of stimulus contrast.

A single split (depth 1) captures only the jump between low and high contrast, with a test error of 22.8 against a noise variance of 9. Depth 3, eight steps, follows the contrast response curve best, at 11.0. Beyond that the steps start to fit noise: the training error keeps falling, to 3.0 at depth 6, while the test error rises again to 13.3, the familiar U from Week 54. A staircase is a crude approximation to a smooth curve, which is one reason single trees are rarely the most accurate models; averaging many of them smooths the staircase, the idea behind Days 3 and 4.
