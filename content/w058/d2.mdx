<PyCell code={String.raw`
  import numpy as np
  import matplotlib.pyplot as plt
  r = np.random.default_rng(582)

  def cells(n, g, flip=0.1):
      y = g.integers(0, 3, n)
      width = np.array([0.25, 0.45, 0.65])[y] + 0.07 * g.normal(size=n)
      rate = np.array([25, 10, 4])[y] * np.exp(0.35 * g.normal(size=n))
      burst = np.array([0.05, 0.2, 0.4])[y] + 0.1 * g.normal(size=n)
      noisy = np.where(g.random(n) < flip, g.integers(0, 3, n), y)
      return np.c_[width, rate, burst, g.normal(size=n), g.random(n)], noisy

  def gini_counts(c):
      n = c.sum(-1, keepdims=True); return 1 - np.sum((c / np.maximum(n, 1)) ** 2, axis=-1)

  def best_split(X, y, K, feats=None, min_leaf=1):
      best = (None, None, np.inf); n = len(y)
      for j in (range(X.shape[1]) if feats is None else feats):
          o = np.argsort(X[:, j]); xs, ys = X[o, j], y[o]
          left = np.cumsum(np.eye(K)[ys], axis=0)[:-1]; right = left[-1] + np.eye(K)[ys[-1]] - left
          nl = np.arange(1, n); nr = n - nl
          imp = (nl * gini_counts(left) + nr * gini_counts(right)) / n
          ok_ = (xs[1:] > xs[:-1]) & (nl >= min_leaf) & (nr >= min_leaf)
          imp = np.where(ok_, imp, np.inf); i = int(np.argmin(imp))
          if imp[i] < best[2]: best = (j, (xs[i] + xs[i + 1]) / 2, imp[i])
      return best

  def grow(X, y, K, depth=99, min_leaf=1, feats_fn=None):
      counts = np.bincount(y, minlength=K)
      if depth == 0 or len(y) < 2 * min_leaf or counts.max() == len(y): return ("leaf", counts)
      j, t, imp = best_split(X, y, K, None if feats_fn is None else feats_fn(), min_leaf)
      if j is None or imp >= gini_counts(counts): return ("leaf", counts)
      m = X[:, j] <= t
      return ("node", j, t, grow(X[m], y[m], K, depth - 1, min_leaf, feats_fn), grow(X[~m], y[~m], K, depth - 1, min_leaf, feats_fn), counts)

  def predict_proba(tree, X, K):
      if tree[0] == "leaf": return np.tile(tree[1] / tree[1].sum(), (len(X), 1))
      _, j, t, L, R, _c = tree; m = X[:, j] <= t; out = np.zeros((len(X), K))
      out[m], out[~m] = predict_proba(L, X[m], K), predict_proba(R, X[~m], K); return out

  def n_leaves(tree):
      return 1 if tree[0] == "leaf" else n_leaves(tree[3]) + n_leaves(tree[4])

  X, y = cells(300, r); X_te, y_te = cells(3000, r)
  acc = lambda tree, X_, y_: np.mean(predict_proba(tree, X_, 3).argmax(1) == y_)
  print("ready: 300 training neurons, 3,000 test neurons, 10% of labels flipped")

The depth at which a tree should stop depends on the noise in the labels, which is usually unknown; hence cross-validation.

<Step n={2} title="Choosing size by cross-validation" minutes={25} />

Depth is one way to limit a tree. Another is a **minimum leaf size**: never create a leaf with fewer than some number of examples. It adapts better to uneven data, stopping early where data are sparse and growing further where they are dense.

The cross-validation table favours shallow trees with a modest minimum leaf size: depth 3 or 4 with leaves of at least five neurons scores 87.3%. A large minimum leaf (15 or 30) gives the same 83% whatever the depth, because it stops the tree well before depth matters. Both controls work; a minimum leaf size has the advantage of adapting to how many examples reach each part of the tree.

<Step n={3} title="Pruning back" minutes={25} />

Stopping rules can stop too early: a split that looks useless may enable good splits below it. The alternative is to grow a full tree and then **prune** it, replacing subtrees by leaves when that does not hurt. CART's cost-complexity pruning does this along a path indexed by a penalty per leaf; a simpler version, **reduced-error pruning**, works bottom-up on a held-out validation set, collapsing any node whose subtree is no better on validation data than a single leaf would be.

Grown without limit on 200 training neurons, the tree has 33 leaves and 78.9% test accuracy. Pruning against the 100 validation neurons collapses it to 10 leaves and raises test accuracy to 87.4%, as good as the best depth-limited tree, without having to choose a depth in advance. Pruning bottom-up keeps splits that look weak on their own but enable useful splits below them, which early stopping would never reach. The cost is that 100 neurons were set aside for validation; CART's cost-complexity pruning chooses its penalty by cross-validation instead, using every example.

A procedure is **unstable** if small changes in the training data cause large changes in the fitted model. Trees are the classic example: if two splits are nearly equally good at the root, a few examples decide which wins, and the whole tree below changes. Measure it.

The tree grown on the original data puts spike width at its root, but across 20 bootstrap resamples only 14 do the same; the other 6 start with firing rate, which answers the prediction (about two thirds, neither all nor almost none). Even among trees that agree on the feature, the threshold wanders, from 0.35 to 0.57 ms: sometimes separating fast-spiking cells from the rest, sometimes pyramidal cells. Deep trees disagree with each other on 18% of test neurons, shallow ones on 12%. Spike width and firing rate carry overlapping information, so the root choice is close to a coin toss decided by a handful of neurons, and everything below the root inherits that choice. Any statement like "spike width is the primary determinant of cell type" drawn from one tree would be fragile.

<Key title="Before you go">
<ul>
<li>Unrestricted trees memorise noise; depth and leaf size must be chosen by validation.</li>
<li>Pruning a fully grown tree avoids stopping too early.</li>
<li>Single trees are unstable: resampling changes their structure and their predictions.</li>
<li>Read a tree's rules only after checking that they survive resampling.</li>
</ul>
