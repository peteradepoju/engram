<Step n={1} title="Learning from mistakes" minutes={20} />

A **weak learner** is one that does a little better than chance, such as a decision **stump**, a tree with a single split. Boosting combines many weak learners into a strong one by training them in sequence, each on a version of the problem that emphasises the previous learners' mistakes. Freund and Schapire's AdaBoost (1997) does this by reweighting examples; Friedman's gradient boosting, today's paper, generalised it by noticing that boosting is gradient descent, so that any differentiable loss can be boosted.

<Step n={2} title="AdaBoost with stumps" minutes={30} />

AdaBoost keeps a weight $w_i$ on each training example, starting equal. In round $t$ it fits a stump $h_t$ that minimises the weighted error $\epsilon_t$, gives it a vote $\alpha_t = \frac12\log\frac{1 - \epsilon_t}{\epsilon_t}$, and multiplies the weights of misclassified examples by $e^{\alpha_t}$ and of correct ones by $e^{-\alpha_t}$, before renormalising. The final classifier is $\text{sign}\left(\sum_t\alpha_th_t(\mathbf x)\right)$. Hard examples gain weight until some stump gets them right.

A single stump is right on about 63% of test trials, because one straight cut cannot carve a disc out of a square. Ten rounds of AdaBoost lift that to about 87%, and accuracy then stays near 87 to 88% for hundreds more rounds, close to the 95% ceiling set by the flipped labels. Each stump is a step in one coordinate, so the ensemble is a sum of a function of $x_1$ and a function of $x_2$; a circle, $x_1^2 + x_2^2$, happens to be exactly that kind of sum, which is why stumps can approximate it. Notice also that test accuracy hardly falls as rounds pile up even though the training set has noisy labels. This resistance to overfitting puzzled people for years; one explanation is that later rounds keep enlarging the margin of the training examples, the same quantity a support vector machine maximises (Week 57).

<Step n={3} title="Gradient boosting" minutes={30} />

<Derivation title="Boosting is gradient descent on functions">
<div>

Build a model $F_M(\mathbf x) = F_0 + \sum_{m=1}^M \nu h_m(\mathbf x)$ step by step, to minimise a loss $\sum_i L(y_i, F(\mathbf x_i))$. Think of the vector of predictions $(F(\mathbf x_1), \dots, F(\mathbf x_n))$ as the thing being optimised.

</div>
<div>

Gradient descent would move each prediction against the gradient, by $-\partial L/\partial F(\mathbf x_i)$. Call these numbers the **pseudo-residuals** $r_i$. For squared loss $\frac12(y - F)^2$, they are exactly the residuals $y_i - F(\mathbf x_i)$.

</div>
<div>

But a model must predict for new inputs too, so instead of moving each prediction freely, fit a small tree $h_m$ to the pseudo-residuals and move along it: $F_m = F_{m-1} + \nu h_m$. The tree is the closest available direction to the negative gradient, and $\nu$, the **learning rate** or shrinkage, is the step size. Changing the loss changes only the pseudo-residuals, which is how the same algorithm boosts logistic, Poisson or robust losses.

</div>
</Derivation>

Training and test error fall together for the first hundred or so rounds, then test error flattens near 6.8 while training error keeps creeping down. The floor is well above the noise variance of 2.25, and the reason is the shape of the model rather than its size: stumps produce a sum of one-feature functions, and the true surface multiplies an orientation tuning curve by a contrast gain. No sum of separate functions of orientation and contrast can represent that product exactly. Trees of depth two or three, which can split on orientation and then on contrast, capture such interactions, and this is why practical gradient boosting uses small trees rather than stumps. Check which features the stumps chose: the irrelevant third feature should be picked rarely, if ever.

<Step n={4} title="Shrinkage and early stopping" minutes={25} />

Boosting keeps reducing training error as rounds are added, so it will eventually fit noise. Two controls work together: a small learning rate makes each round cautious, and **early stopping** halts at the round with the lowest error on validation data.

With a learning rate of 0.8 the validation error bottoms out at about 8.6 by round 42 and then climbs to almost 9.9 as later rounds fit noise in the 350 fitting examples. With 0.05 the curve is still falling slowly at round 400 and is already lower, at about 7.8. Remember that the validation set used to stop is now part of model selection, so the final performance estimate still needs a separate test set (Week 59).
