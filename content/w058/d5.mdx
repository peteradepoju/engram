<Step n={1} title="Regression forests for a firing rate" minutes={25} />

A regression tree predicts the mean of the training targets in each leaf and chooses splits that most reduce the sum of squared errors. A regression forest averages many such trees, each grown on a bootstrap resample with a random subset of features at each split. The setup cell builds one, for a simulated hippocampal or visual cortical neuron whose rate depends on running speed, on the direction of a moving stimulus, and on whether the trial is rewarded, with speed and reward interacting.

<PyCell code={String.raw`
  import numpy as np
  import matplotlib.pyplot as plt
  r = np.random.default_rng(585)
  names = ["speed", "direction", "reward", "noise_cont", "noise_bin"]

  def session(n, g):
      speed = g.uniform(0, 1, n)                         # normalised running speed, many distinct values
      direction = g.integers(0, 4, n)                    # one of four stimulus directions
      reward = g.integers(0, 2, n)                       # rewarded or not
      noise_cont = g.uniform(0, 1, n)                    # irrelevant, continuous
      noise_bin = g.integers(0, 2, n)                    # irrelevant, binary
      rate = 5 + 4 * speed + 3 * np.cos(np.pi * direction / 2) + 6 * speed * reward
      X = np.column_stack([speed, direction, reward, noise_cont, noise_bin]).astype(float)
      return X, rate + 1.5 * g.normal(size=n), rate

  def best_split(X, y, feats, min_leaf):
      n, best = len(y), (None, 0.0, 0.0)
      for j in feats:
          o = np.argsort(X[:, j]); xs, ys = X[o, j], y[o]
          cs = np.cumsum(ys)[:-1]; nl = np.arange(1, n)
          gain = cs ** 2 / nl + (ys.sum() - cs) ** 2 / (n - nl) - ys.sum() ** 2 / n
          ok = (xs[1:] > xs[:-1]) & (nl >= min_leaf) & (n - nl >= min_leaf)
          gain = np.where(ok, gain, -np.inf); k = int(np.argmax(gain))
          if gain[k] > best[2]: best = (j, (xs[k] + xs[k + 1]) / 2, gain[k])
      return best

  def grow(X, y, g, mtry, min_leaf, imp_acc):
      if len(y) < 2 * min_leaf: return ("leaf", y.mean())
      feats = g.choice(X.shape[1], mtry, replace=False)
      j, t, gain = best_split(X, y, feats, min_leaf)
      if j is None: return ("leaf", y.mean())
      imp_acc[j] += gain                                 # reduction in squared error from this split
      m = X[:, j] <= t
      return ("node", j, t, grow(X[m], y[m], g, mtry, min_leaf, imp_acc), grow(X[~m], y[~m], g, mtry, min_leaf, imp_acc))

  def predict(tree, X):
      if tree[0] == "leaf": return np.full(len(X), tree[1])
      _, j, t, L, R = tree; m = X[:, j] <= t; out = np.empty(len(X))
      out[m], out[~m] = predict(L, X[m]), predict(R, X[~m]); return out

  def forest(X, y, g, n_trees=40, mtry=2, min_leaf=3):
      imp_acc, trees = np.zeros(X.shape[1]), []
      for b in range(n_trees):
          idx = g.integers(0, len(y), len(y))
          trees.append(grow(X[idx], y[idx], g, mtry, min_leaf, imp_acc))
      return trees, imp_acc / imp_acc.sum()

  fpredict = lambda trees, X: np.mean([predict(t, X) for t in trees], axis=0)
  r2 = lambda y_, p: 1 - np.mean((y_ - p) ** 2) / np.var(y_)

  X, y, _ = session(400, r); X_te, y_te, rate_te = session(2000, r)
  trees, imp_impurity = forest(X, y, np.random.default_rng(1))
  p_te = fpredict(trees, X_te); r2_te = r2(y_te, p_te)
  print(f"forest test R squared {r2_te:.3f}; ceiling set by the noise {r2(y_te, rate_te):.3f}")

The forest explains about 77% of the variance in test firing rates, against a ceiling of about 84% set by the trial-to-trial noise. That is a good model, and we know the truth: rate depends on speed, direction and reward, with speed's effect larger on rewarded trials, and not at all on the two noise columns. The question for the rest of the day is whether the interpretation tools recover that truth.

<Step n={2} title="Two kinds of importance" minutes={30} />

**Impurity importance**, the default in most software, adds up the error reduction of every split on a feature, across all trees. **Permutation importance** asks a more direct question: if the values of one feature on held-out trials are shuffled, breaking its link to the target while keeping its distribution, how much worse do the predictions become? Strobl and colleagues (2007), today's paper, showed that the first is biased in favour of features with many possible split points.

Permutation importance gets the story right: shuffling speed raises the error by about 68% of the target variance, direction by 48% and reward by 41%, while shuffling either noise column changes nothing (the tiny negative values are chance). Impurity importance ranks the real features in the same order, but gives the continuous noise column about 10% of the total, five times as much as the binary noise column. Deep trees split on the noise column to separate the last few training trials in a leaf, and a continuous feature offers hundreds of thresholds to choose from, so by chance one of them always reduces training error a little. Strobl and colleagues traced this bias to the selection of split variables and proposed conditional inference trees and a conditional permutation importance as remedies. The practical rule: compute importance by permutation, on held-out data.

<Step n={3} title="Correlated features" minutes={20} />

Suppose the rig records running speed twice, from a treadmill encoder and from video, and both go into the model. Permuting one copy now breaks little, because the forest can fall back on the other. Importance is about what the model uses, not about what the brain uses.

With the copy present, the permutation importance of speed falls from 0.68 to 0.14, and the copy picks up 0.22. Together they still carry less than speed did alone, because when either is shuffled the forest can lean on the other. Prediction is just as good as before (R squared 0.755 against 0.768), so the model has not changed its view of the neuron; only the attribution has. A careless reading would conclude that speed matters far less than direction or reward. With correlated recordings, from overlapping neurons to related task variables, permute groups of correlated features together, or report the importance of the group.

<Step n={4} title="Partial dependence and ICE curves" minutes={30} />

Importance says how much a feature matters, not how. A **partial dependence** plot answers how, on average: set the feature to a value $v$ on every trial, predict, average, and repeat over a grid of $v$. An **individual conditional expectation** (ICE) curve does the same for a single trial without averaging. Where the ICE curves are parallel the feature acts on its own; where they fan out, it interacts with something else.

The partial dependence on speed rises from about 6 to about 11 spikes per second across the grid: speed matters, and its average effect is roughly linear, though the forest's step functions show through. The ICE curves split it apart. On rewarded trials the predicted rate rises by about 7.5 across the grid, on unrewarded trials by about 3.2, against true values of 9.0 and 3.6 (the forest shrinks slopes a little, because leaf averages flatten the edges of the range). The average curve, a single gentle slope, hides that reward multiplies the effect of speed, which is the kind of gain modulation that matters most to a neuroscientist.

<Callout kind="warning" title="A model of the data, not of the brain">

Every tool today describes the fitted forest. A feature can be important to the model because it is correlated with the true cause, and unimportant because a correlated copy took its place. Partial dependence plots also evaluate the model at combinations of features that never occur together, such as high running speed on a trial where the animal sat still, where the forest's predictions are guesses. To make claims about the neuron, combine these tools with experimental control or with the causal methods of Week 72.

<Key title="Before you go">
<ul>
<li>Regression forests average regression trees, each predicting leaf means.</li>
<li>Impurity importance favours features with many split points; permutation importance on held-out data does not.</li>
<li>Correlated features share importance, so a low score does not mean a feature is irrelevant.</li>
<li>Partial dependence shows average effects; ICE curves show the interactions the average hides.</li>
</ul>
