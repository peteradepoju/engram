<Step n={1} title="Selecting and measuring in the same data" minutes={30} />

A **circular analysis** uses the data to choose what to analyse and then tests or measures that choice on the same data. Selecting neurons that prefer condition A, then reporting how much they prefer A; choosing the time window where a decoder peaks, then reporting the peak accuracy; defining a region by its response to faces, then showing that it responds to faces. In each case noise that helped an item pass the selection is counted as signal. Kriegeskorte, Simmons, Bellgowan and Baker (2009), today's paper, called it double dipping, showed it in a sample of published studies, and gave the remedy: the data used for selection and for measurement must be independent.

Selecting all 400 neurons with a t-statistic above 2 picks 25, and their circular A minus B estimate is 0.78, more than three times their true mean effect of 0.22 (and larger than the strongest true effect in the population, 0.5). Many of the selected neurons have no true preference at all and passed by chance, and the true ones passed partly because their noise happened to favour A. Selecting on the first ten trials and measuring on the last ten gives 0.11 for a set whose true mean effect is 0.11: unbiased. The price is power, since each half has only ten trials; that is the honest price of asking the data two questions.

<Step n={2} title="Regression to the mean" minutes={20} />

Selection on one occasion and measurement on another is not circular, but it carries a related trap. Items selected for extreme values on a noisy measurement will on average be less extreme next time, simply because part of what made them extreme was noise that does not repeat. Galton found it in the heights of parents and children (Week 55); in neuroscience it can look like adaptation, plasticity or learning.

The neurons that responded most on day 1, averaging 7.2, average 5.9 on day 2; the weakest rise from 2.6 to 3.9. Nothing changed. Half the spread between neurons on any one day is measurement noise, so the extremes on day 1 are partly extreme noise, which does not repeat. Report it as adaptation in the strong cells and facilitation in the weak ones and it would look like homeostatic plasticity. The fix is the same as before: select the neurons on independent data, such as a separate set of trials on day 1, and compare days on data not used for selection, or analyse all neurons without selecting.

<Step n={3} title="An audit" minutes={40} />

Below is a complete analysis, of the kind that appears in many papers' methods. 120 trials in blocks of 20 alternate between two conditions; 500 neurons were recorded. The pipeline z-scores every neuron using all trials, keeps the 20 neurons that best separate the conditions, and reports 5-fold cross-validated accuracy of a nearest-centroid decoder with random folds. The data contain drift and no condition signal at all. Find every leak and write an honest version.

  T = 120
  y_a = (np.arange(T) // 20) % 2
  X_a = np.cumsum(0.25 * ga.normal(size=(T, 500)), axis=0) + ga.normal(size=(T, 500))

  def select(X, y, k=20):
      return np.argsort(np.abs(X[y == 1].mean(0) - X[y == 0].mean(0)))[-k:]

  def centroid_score(Xtr, ytr, Xte, yte):
      c0, c1 = Xtr[ytr == 0].mean(0), Xtr[ytr == 1].mean(0)
      return np.sum((((Xte - c1) ** 2).sum(1) < ((Xte - c0) ** 2).sum(1)) == yte)

  def published_pipeline(X, y):
      Z = (X - X.mean(0)) / X.std(0)                         # leak 1: statistics from all trials
      f = select(Z, y)                                       # leak 2: selection on all trials
      folds = np.array_split(np.random.default_rng(0).permutation(len(y)), 5)   # leak 3: random folds
      right = 0
      for te in folds:
          tr = np.setdiff1d(np.arange(len(y)), te)
          right += centroid_score(Z[tr][:, f], y[tr], Z[te][:, f], y[te])
      return right / len(y)

  def honest_pipeline(X, y):
      folds = np.array_split(np.arange(len(y)), 3)           # pairs of whole blocks, one of each condition
      right = 0
      for te in folds:
          tr = np.setdiff1d(np.arange(len(y)), te)
          mu, sd = X[tr].mean(0), X[tr].std(0)
          Ztr, Zte = (X[tr] - mu) / sd, (X[te] - mu) / sd

The published pipeline reports 72.5% on data with no condition signal. Each of its three leaks contributes: the global z-scoring is the mildest, the selection of 20 neurons from 500 using all trials is the strongest, and the random folds let drift do the rest. The honest pipeline reports 40%. That is below chance, and it is not a bug: with only three folds and strong drift, a test pair of blocks sits next to training blocks of the opposite condition, so honest estimates on drifting data swing widely around chance, above or below. A permutation test of the honest pipeline (Day 4) would show that 40% is entirely consistent with no signal. The lesson is not only that the published number was wrong, but that with six blocks this experiment cannot measure a small effect at all, which is a design problem no analysis can fix.

<Step n={4} title="Habits that prevent it" minutes={15} />

None of today's errors needs bad intent; each is the natural first way to write the analysis. Habits help more than vigilance:

<ul>
<li>Write the whole analysis as one function from raw data to score, and cross-validate the function. Anything outside it that touches the labels is a suspect.</li>
<li>Decide the splitting unit before looking at results, from the claim you want to make.</li>
<li>Run the full pipeline on shuffled labels and on simulated null data. If it finds signal there, it is leaking.</li>
<li>Keep a lockbox: a portion of the data, such as one session or one animal, that is analysed once, at the end, with the final pipeline.</li>
<li>Preregister the analysis, or at least write it down and date it, before running it on the final data.</li>
</ul>

<Key title="Before you go">
<ul>
<li>Selecting and measuring in the same data inflates effects, sometimes from nothing.</li>
<li>Independent halves for selection and measurement give honest estimates.</li>
<li>Regression to the mean can masquerade as adaptation or learning.</li>
<li>Write analyses as single functions, test them on null data, and keep a lockbox.</li>
</ul>
