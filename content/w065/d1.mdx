<Step n={1} title="The model and the three questions" minutes={20} />

A **hidden Markov model** has a discrete state $z_t$ that evolves by a transition matrix $A_{jk} = p(z_t = k \mid z_{t-1} = j)$ from an initial distribution $\boldsymbol\pi$, and observations drawn from an emission distribution $p(x_t \mid z_t)$. Rabiner (1989), today's paper, organised the subject around three problems: **evaluation**, the probability of an observation sequence; **decoding**, the states behind it; and **learning**, the parameters (Day 2). In neuroscience the states might be up and down states, behavioural syllables, sleep stages or task strategies.

<Step n={2} title="Forward and backward" minutes={30} />

The **forward** recursion propagates $\alpha_t(k) \propto p(z_t = k, x_{1:t})$ and gives both the filtered posterior $p(z_t \mid x_{1:t})$ and the likelihood of the data; the **backward** recursion adds the evidence from the future, and their product gives the **smoothed** posterior $p(z_t \mid x_{1:T})$. Normalising each forward step keeps the numbers from underflowing and the normalisers multiply to the likelihood, so their logs sum to the log-likelihood.

  def forward(B, A, pi):
      T_, K = B.shape
      alpha = np.zeros((T_, K)); c = np.zeros(T_)
      a = pi * B[0]; c[0] = a.sum(); alpha[0] = a / c[0]
      for t in range(1, T_):
          a = B[t] * (alpha[t - 1] @ A)
          c[t] = a.sum(); alpha[t] = a / c[t]
      return alpha, c

      T_, K = B.shape
      beta = np.ones((T_, K))
      for t in range(T_ - 2, -1, -1):
          beta[t] = (A @ (B[t + 1] * beta[t + 1])) / c[t + 1]
      return beta

Filtering, which sees only the past, labels 81% of bins correctly; smoothing, which also uses the future, 84%. The gain comes at the state boundaries: when a run of high counts begins, the filter needs several bins to become confident, while the smoother knows how the run continued and places the transition where it belongs. For an online application, a prosthesis or a closed-loop experiment, only the filtered estimate is available; for analysis of a recording, there is no reason not to smooth.

<Step n={3} title="Viterbi" minutes={30} />

The **Viterbi algorithm** finds $\arg\max_{z_{1:T}}p(z_{1:T} \mid x_{1:T})$, the single most likely sequence. It is the forward recursion with sums replaced by maxima, run in logarithms, with a record of which predecessor achieved each maximum so that the path can be traced back:

$$
\delta_t(k) = \log p(x_t \mid z_t = k) + \max_j\left[\delta_{t-1}(j) + \log A_{jk}\right].
$$

The Viterbi path is right on 86% of bins with 7 switches, exactly the number the true sequence made; pointwise smoothed decoding gets 84% with 9 switches; thresholding counts at 2.8 gets 68% with 134 switches, because a single quiet bin inside an up state is read as a transition. Note also the log joint probabilities: Viterbi's path scores $-614.9$, higher than the pointwise path's $-623.3$ and higher even than the true sequence's $-627.4$. That is not a bug. The most likely path is usually smoother than the truth, since the truth includes transitions the data do not support.

<Step n={4} title="When paths and marginals disagree" minutes={25} />

Pointwise decoding maximises the expected number of correct states; Viterbi maximises the probability of the whole sequence. They answer different questions, and with transitions that are forbidden or very unlikely, the pointwise sequence can even be impossible under the model.

The smoothed posteriors favour state 0 at the first step and state 2 at the third, so pointwise decoding returns 0, 2, 2, a sequence whose probability is zero: the transition from 0 to 2 is forbidden. Viterbi returns 0, 0, 0, with log probability $-5.43$. The pointwise answer is still useful, since each of its states separately is the most probable at that time, but it is not a sequence the model could have produced, and presenting it as a segmentation of behaviour would be a mistake. Report posteriors when asking about individual times, Viterbi when asking for a single trajectory.
